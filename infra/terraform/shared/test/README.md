# Shared test Terraform root

PD-16 owns the shared test-environment root and planned state key `shared/test/terraform.tfstate`; use the default workspace. The root has no backend block and uses the repository's Terraform 1.15.9 pin and locked AWS provider. `deployment_phase` defaults to `disabled`; `base` enables the VPC, one-AZ NAT/ECS/RDS base and the RDS-subnet-only second AZ, while `service` additionally enables the API service. Keep the phase disabled for local checks. The API uses bridge port mapping 8000→18000 for SSM port forwarding and creates no inbound security-group rule. The PostgreSQL probe task and its secret policy remain pending a decision on a dedicated low-privilege database login.

The RDS master password is supplied only to Terraform's ephemeral variable and AWS provider write-only `password_wo` argument. Terraform omits ephemeral values from saved plans/state; see [Terraform write-only arguments](https://developer.hashicorp.com/terraform/language/manage-sensitive-data/write-only). Never commit the password, include it in an ordinary variable file, print it, or put it in an output, tag, user data, or log. Network CIDRs/AZs, RDS sizing/version/backup behavior, log retention, final-snapshot choice, cleanup review date, and API image digest require explicit plan inputs; validation alone does not settle them.

Run the repository's pinned backend-free checks with `make terraform-check`. Do not run a plan or initialize the remote backend until PD-15 backend/migration, the approved non-root planning identity, complete cost/retention inputs, and separate authorization for the exact plan are ready. See [Terraform ownership boundaries](../../../../docs/architecture/terraform-ownership.md) and the [Terraform change workflow](../../README.md).
