# Shared test Terraform root

PD-16 owns the shared test-environment root and state key `shared/test/terraform.tfstate`; use the default Terraform workspace. The S3 backend points to the bucket in `infra/terraform/bootstrap/versions.tf` and the exact shared/test state key; Step 4 local checks remain backend-free. Step 5 checks local/remote state collisions before `terraform init -reconfigure`; never plan against the implicit local backend. The root uses Terraform 1.15.9 and its locked AWS provider. `deployment_phase` defaults to `disabled`; `base` enables the VPC, one-AZ NAT/ECS/RDS base and the RDS-subnet-only second AZ, while `service` additionally enables the API service plus separate one-shot database-login setup and probe tasks. Keep the phase disabled for local checks. The API uses bridge port mapping 8000→18000 for SSM port forwarding and creates no inbound security-group rule. [DEC-05](../../../../docs/decisions/private-postgresql-probe-login.md) records the probe-login boundary: setup can fetch the master and probe parameters; the probe can fetch only its own credential; neither task role receives AWS permissions.

## ECS capacity lifecycle

`api_service_enabled` defaults to `false`; it sets the ECS API service desired count to zero. The ECS capacity provider manages a single-host Auto Scaling group with minimum zero and maximum one, and starts from zero. Enabling the API service during an approved run lets ECS launch capacity; disabling it after all tasks exit lets ECS drain and terminate the empty host. The root EBS volume is deleted with that host. ECS scale-in may take about 15 minutes after the cluster becomes empty. One-shot tasks use the cluster's default capacity-provider strategy and can request a host while they run.

To resume after a run, first start RDS and wait until it is available. Then prepare and review a saved Terraform plan with `api_service_enabled=true`, and apply only after approval for that exact plan. After all tasks exit, prepare and review a separate plan with `api_service_enabled=false`, apply it, and wait for ECS scale-in. Review the account, Region, backend key, exact changes, cost, and plan checksum for each plan. Never stop or terminate the Auto Scaling group's instance directly. Stop RDS after the tasks have exited, using the reviewed operator procedure below; RDS actions need their own explicit authorization and an approved non-root identity. `aws rds stop-db-instance` and `start-db-instance` are operations, not Terraform plan changes. RDS storage and backups remain while it is stopped, and AWS may automatically restart it after seven consecutive days; the selected full-stack idle teardown is after 96 hours.

For each run, record the operator, exact hours/expiry, expected cost, and remaining USD 25 reserve before starting. If the full `shared/test` stack is idle for 96 hours, prepare a destroy plan for that root, review its checksum and snapshots/ECR deletion, and obtain separate approval before applying. Never destroy the PD-15 state backend or its versioned state during PD-16 cleanup. These instructions describe a future gated workflow; this Step 4 documentation does not authorize or run any AWS operation.

RDS operation templates, after confirming the instance identifier and approval:

```sh
aws rds stop-db-instance --db-instance-identifier <approved-instance-id> --region ap-south-1
aws rds wait db-instance-stopped --db-instance-identifier <approved-instance-id> --region ap-south-1
aws rds start-db-instance --db-instance-identifier <approved-instance-id> --region ap-south-1
aws rds wait db-instance-available --db-instance-identifier <approved-instance-id> --region ap-south-1
```

Do not run these templates during local validation or without the separate target/operation approval.

The RDS master password is supplied only to Terraform's ephemeral variable, RDS write-only `password_wo`, and base-phase Parameter Store `value_wo`. The separate, single-line probe password uses an ephemeral variable and service-phase `value_wo`. Terraform omits both values from saved plans/state; re-supply the same value securely when applying a saved plan, or stop and replan with a password-version update if it changes. See [Terraform write-only arguments](https://developer.hashicorp.com/terraform/language/manage-sensitive-data/write-only). Never commit either password, include it in an ordinary variable file, print it, or put it in an output, tag, user data, task-definition environment field, or log. ECS task definitions contain only SecureString references. The setup task uses psql's `\password` prompt and suppresses SQL diagnostics; the probe task sees only the probe parameter. AWS-managed Parameter Store encryption is used, with task execution policies scoped to exact parameter ARNs.
