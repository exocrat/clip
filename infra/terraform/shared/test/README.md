# Shared test Terraform root

PD-16 owns the shared test-environment root and planned state key `shared/test/terraform.tfstate`; use the default workspace. The root has no backend block and uses the repository's Terraform 1.15.9 pin and locked AWS provider. `deployment_phase` defaults to `disabled`; `base` enables the VPC, one-AZ NAT/ECS/RDS base and the RDS-subnet-only second AZ, while `service` additionally enables the API service plus separate one-shot database-login setup and probe tasks. Keep the phase disabled for local checks. The API uses bridge port mapping 8000→18000 for SSM port forwarding and creates no inbound security-group rule. [DEC-05](../../../../docs/decisions/private-postgresql-probe-login.md) records the probe-login boundary: setup can fetch the master and probe parameters; the probe can fetch only its own credential; neither task role receives AWS permissions.

The RDS master password is supplied only to Terraform's ephemeral variable, RDS write-only `password_wo`, and base-phase Parameter Store `value_wo`. The separate, single-line probe password uses an ephemeral variable and service-phase `value_wo`. Terraform omits both values from saved plans/state; re-supply the same value securely when applying a saved plan, or stop and replan with a password-version update if it changes. See [Terraform write-only arguments](https://developer.hashicorp.com/terraform/language/manage-sensitive-data/write-only). Never commit either password, include it in an ordinary variable file, print it, or put it in an output, tag, user data, task-definition environment field, or log. ECS task definitions contain only SecureString references. The setup task uses psql's `\password` prompt and suppresses SQL diagnostics; the probe task sees only the probe parameter. AWS-managed Parameter Store encryption is used, with task execution policies scoped to exact parameter ARNs. Network CIDRs/AZs, RDS sizing/version/backup behavior, log retention, final-snapshot choice, cleanup review date, and API/PostgreSQL-client image digests require explicit plan inputs; validation alone does not settle them.

Run the repository's pinned backend-free checks with `make terraform-check`. Do not run a plan or initialize the remote backend until PD-15 backend/migration, the approved non-root planning identity, complete cost/retention inputs, and separate authorization for the exact plan are ready. See [Terraform ownership boundaries](../../../../docs/architecture/terraform-ownership.md) and the [Terraform change workflow](../../README.md).
