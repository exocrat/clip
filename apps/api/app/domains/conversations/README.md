# Conversations domain

Owner: D — Rahul for CN-01/CN-02; A — Aditya owns CN-03 notifications, with D reviewing producer/read-state integration. Required implementation belongs to the [domain task list](../../../../../docs/tasks/domain-task-list.md), after the required foundation and contract gates.

`origin_retirement.py` implements the internal `get_origin_activity` and `mark_origin_retired` database operations. `thread_creation.py` implements the internal Listing and Wanted Request conversation open/create operations. Both providers are tested directly, but neither is wired by `main.py` or exposed as a route. Thread creation trusts server-resolved contexts from Listings/Search, checks participant eligibility through Identity's public interface, and atomically records the thread, its two members, and one initial notification intent. It reads no Listings or Search tables. It does not delete origin content or claim real Listings/Search integration. The future `notifications/` subtree is reserved for A; other conversation/offer implementation remains D-owned. Shared technical primitives belong in `app.core`; cross-domain calls use reviewed public interfaces. Message APIs, encryption, notification delivery, and the rest of the Conversations provider remain unimplemented.
