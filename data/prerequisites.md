# Synthetic-data scope and later prerequisites

**Origin:** PD-09 Step 1, 2026-10-18. **Owner:** Mohit (C); peer: Suraj (B).

PD-09 prepares schema-independent generator/manifest tooling and a query-label
format. It does not load the database, implement domain behavior, create final
reference records or manufacture relevance judgments. This branch starts at
PD-08 checkpoint `b6bade4`; Mohit verified proceeding with this bounded scope
while PD-08's deferred checks and affected-owner acceptance remain open.

## Requirements and boundaries

| Source | Requirement for the framework / later consumer |
|---|---|
| [PD-09](../docs/tasks/pre-domain-task-list.md#pd-09--prepare-deterministic-synthetic-data-tooling) | Explicit seed/counts, fictitious values, reserved test domains, stable IDs, validation hooks and reproducible logical data. Versioned manifests contain requested/observed counts, UTC run time and a fingerprint excluding variable run-time metadata. |
| [Shared conventions](../docs/conventions/shared-conventions-and-cross-domain-contract-rules.md) and [UUID decision](../docs/decisions/identifiers.md) | IDs are lowercase hyphenated UUIDv4 strings. Deterministic synthetic IDs must preserve the approved shape and remain test-only; no UUIDv5 substitution or shared-helper edit. IDs never establish authorization. |
| [Timestamp decision](../docs/decisions/timestamps.md) | Aware UTC; wire format has six fractional digits and `Z`. A recorded generation time must not perturb logical-data fingerprints. Any synthetic logical clock must be an explicit reproducible input, not wall-clock-dependent record content. |
| [Money decision](../docs/decisions/money.md) | Future adapters use integer paise, reject bool/float money and preserve whole-rupee multiples of 100. Seller price is required, budget optional and negotiability separate; final field mapping belongs to real adapters. |
| [Product NFRs](../docs/product/product-reference-and-architecture-decisions.md) / [SE-01](../docs/tasks/domain-task-list.md#se-01--implement-browse-search-filters-sorting-and-pagination) | DATA-READY later requires at least 5,000 users, 1,000 listings and 20 manually reviewed representative queries. NFR-04 later measures Success@5 >=80% on that frozen set. Preview counts/fingerprints are not this acceptance evidence. |
| [Fixture safety](../tests/fixtures/core/README.md) | Controlled fictitious data only. No real contacts, passwords, credentials, private keys, OTPs, ciphertext exports, network/provider calls or production loading. Contact-shaped examples use reserved test domains only. |

The framework must expose versioned preview records and validation/adapter hooks,
not guess final user/listing fields or hard-code foundation SQL as the final
domain schema. Query-label templates start without final listing IDs or claimed
relevance. Generated outputs must be separate from tracked source/configuration;
overwrite must be explicit and scoped to generated local files, never a database
reset. Exact record/manifest/label formats are outputs of Steps 2, 3 and 5.
